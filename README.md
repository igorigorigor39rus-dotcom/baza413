Пересечения GPS-трека разрешены: в зачёт идёт площадь внутри внешних границ. Допуск замыкания и погрешность GPS — до 20 м. Трансляция Telegram сама запускает фоновую прогулку; кнопки в чате завершают или отменяют её. В ТОП-10 есть фото и две вкладки: 🦴 и площадь. Карты остаются OpenStreetMap + OpenTopoMap без платного ключа.

# Telegram + GitHub Pages + Supabase

**Без VPS и постоянно включённого компьютера.** GitHub Pages размещает карту по HTTPS. Supabase хранит данные и обрабатывает запросы. Бот отвечает через webhook в Supabase, поэтому Python-процесс с polling больше не нужен.

Настроен публичный адрес проекта: **https://fywsqxijebneqkxusgro.supabase.co**. Одного идентификатора недостаточно для установки: миграцию, функцию, секреты и GitHub Pages владелец включает по шагам ниже. Удалённая база и бот автоматически не изменялись.

## Что работает в коде

- Профиль питомца: кличка, возраст, описание, фотография и цвет.
- OpenStreetMap-карта внутри Telegram Mini App.
- GPS через Telegram LocationManager, при его отсутствии — браузерный Geolocation.
- Фото в рейтинге и досье можно открыть крупно. ТОП-10 сортируется по 🦴 или текущей площади.
- Покупка: отметьте 3–100 точек на карте, проверьте серверную цену, подтвердите списание. Чужая площадь недоступна для покупки; своя объединяется с покупкой; купленный участок приносит доход и может быть перезахвачен прогулкой.
- «Начать захват» → замкнуть контур в пределах 20 м → «Захватить».
- Общие территории в PostGIS: пересечение переходит новому владельцу, непересечённая часть, отверстия и островки сохраняются.
- Вход проверяется по Telegram HMAC на сервере. В браузере нет токена бота и service_role.
- Изменение владельцев — атомарная операция PostgreSQL. Повтор захвата после потери ответа возвращает прежний результат, а не создаёт дубликат.
- Локальное демо `?demo=1` работает без Supabase и Telegram; оно не меняет настоящую карту.

**Сначала скачайте свежий архив релиза v.0.7 в новую папку:** [ZIP](https://github.com/igorigorigor39rus-dotcom/baza413/archive/refs/tags/v.0.7.zip).

## Шаг 1. Включите GitHub Pages

Откройте репозиторий `igorigorigor39rus-dotcom/baza413` → **Settings → Pages**.

1. В **Build and deployment → Source** выберите **Deploy from a branch**.
2. Ветка — **prototype**, папка — **/docs**.
3. Нажмите **Save**, дождитесь завершения публикации GitHub.

Ожидаемый адрес: **https://igorigorigor39rus-dotcom.github.io/baza413/**.

После включения сразу можно открыть демо: **https://igorigorigor39rus-dotcom.github.io/baza413/?demo=1**. Создайте профиль → «Пройти демомаршрут» → четыре раза «Следующая точка» → «Захватить». Пробные данные остаются только в localStorage вашего браузера. Настоящий вход выполняется через кнопку бота.

Если Pages недоступен для вашего репозитория/тарифа, не меняйте приватность репозитория автоматически: сначала выберите подходящий вариант размещения. Ветка main здесь не меняется.

## Шаг 2. Установите таблицы и функции Supabase

Откройте [свой проект Supabase](https://supabase.com/dashboard/project/fywsqxijebneqkxusgro).

1. Откройте **SQL Editor → New query**.
2. Скопируйте **весь** файл [supabase/migrations/202611050001_paws.sql](supabase/migrations/202611050001_paws.sql).
3. Вставьте SQL и нажмите **Run**. Дождитесь успешного завершения.
4. Для первой установки затем выполните целиком `supabase/migrations/202611060005_v07.sql`. Уже работающий проект обновляется только этим новым файлом по инструкции выше.

Каждый SQL-файл выполняется одной транзакцией. Создаются отдельная схема `paws`, таблицы, RPC-функции с префиксом `paws_` и bucket `paws-photos`. Существующие таблицы вне этой схемы не удаляются. Миграция рассчитана на новую схему приложения; если у вас уже есть несвязанная схема `paws`, остановитесь и согласуйте другое имя.

PostGIS включается при необходимости. Если он уже установлен, используется его существующая схема, без переноса расширения. Повторное применение этой же миграции сохраняет данные приложения. Для просмотра таблиц в Table Editor выберите схему **paws**.

Таблицы закрыты RLS. У `anon` и `authenticated` нет прямого доступа и прав запуска RPC. Запросы проходят через Edge Function, где проверяется Telegram, затем вызывается конкретная SQL-функция серверным ключом. Supabase Auth и браузерный anon/publishable key для этой схемы не нужны.

## Шаг 3. Задайте секреты функции

В Supabase откройте **Edge Functions → Secrets** и добавьте:

| Имя | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Ваш новый токен BotFather после `/revoke`. Не используйте ранее отправленный в чат токен. |
| `APP_URL` | `https://igorigorigor39rus-dotcom.github.io/baza413/` — включая завершающий `/`. |
| `WEBHOOK_SECRET` | Случайная строка из 32–256 латинских букв, цифр, `_` и `-`, например сгенерированная менеджером паролей. Сохраните её для шага 5. |

Не присылайте значения в чат, не добавляйте их в GitHub или `web/config.mjs`. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase предоставляет функции автоматически — копировать серверный ключ в браузер не нужно.

В `web/config.mjs` хранится только публичный URL проекта.

## Шаг 4. Загрузите Edge Function

На вашем компьютере откройте терминал **в папке скачанного проекта**, рядом с папкой `supabase`. Для CLI нужен установленный Node.js 20+; Node нужен только для разовой загрузки, не для работы приложения. Ваш Node 26 подходит по версии, поддержку конкретной платформы проверяет сам CLI.

Выполните по очереди:

```sh
npx supabase login
npx supabase functions deploy paws-api --project-ref fywsqxijebneqkxusgro --no-verify-jwt
```

Первая команда предложит вход в Supabase. Выполняйте его в своём браузере/терминале, не передавайте access token в чат. Вторая загрузит функцию из `supabase/functions/paws-api`.

`--no-verify-jwt` относится **только к нашей функции**: она проверяет подпись Telegram и отдельный секрет webhook самостоятельно. Это не означает отключение входа в коде. Без флага gateway может отклонять Telegram-запросы до нашей проверки.

После успешной загрузки проверка готовности:

**https://fywsqxijebneqkxusgro.supabase.co/functions/v1/paws-api/health**

Ожидается `{"ok":true,"version":"0.7.0"}`. Если возвращается ошибка, проверьте миграцию и Secrets. Сам по себе успешный deploy ещё не подтверждает работу базы.

## Шаг 5. Подключите webhook существующего бота

Если где-то запущен старый Python-бот с polling, сначала остановите его. Новый webhook заменяет прежний webhook этого бота — используйте бота, предназначенного для приложения.

Нужен установленный Python 3.12, но лишь для однократной команды настройки; дополнительные библиотеки для скрипта не требуются.

Windows:

```bat
py -3.12 "./scripts/configure_supabase_bot.py"
```

macOS / Linux:

```sh
python3.12 scripts/configure_supabase_bot.py
```

Скрипт проверит наличие GitHub Pages, API и базы, затем попросит **действующий токен** и **тот же WEBHOOK_SECRET**, который вы сохранили в Supabase. При вводе символы не отображаются. Секреты не записываются на диск и не печатаются.

После проверки он установит webhook, команды `/start`, `/help`, `/privacy`, `/status`, `/capture`, `/cancel` и кнопку меню «Карта». Накопленные сообщения не удаляются. Ошибки настройки не раскрывают URL с токеном.

Откройте личный чат своего бота → `/start` → **«🐾 Карта и досье»**. Webhook принимает `message`, `edited_message` и `callback_query`: обновления геопозиции и кнопки управления. После работающей v.0.6 webhook повторно настраивать не нужно; при обновлении более старой версии повторите настройку скриптом с прежними действующим токеном и WEBHOOK_SECRET. После этой настройки компьютер можно выключить: работают GitHub Pages и Supabase.

## Проверка на телефоне

1. Создайте настоящий профиль через кнопку бота. Он не связан с браузерным демо.
2. Выйдите на открытое место, нажмите «Начать захват», разрешите точную геолокацию.
3. Обойдите простой контур, вернитесь к старту и нажмите «Захватить».
4. Нажмите на маркер владельца, проверьте описание и фотографию.
5. Другой пользователь открывает того же бота и обходит пересекающийся участок: непересечённая часть должна остаться прежнему владельцу.

Геолокация требует HTTPS и разрешений Telegram/ОС. Обычная запись требует открытого Mini App; фон или блокировка экрана прерывают её. Для выключенного экрана используйте отдельный режим Telegram по [инструкции прогулки](guide/UPDATE_V0_6.md#6-как-теперь-гулять). Он зависит от телефона, разрешений и частоты обновлений Telegram; при пропусках или недостаточной точности захват отклоняется. Wake Lock доступен не во всех клиентах.

Порог замыкания 20 м применяется к **измеренным** координатам: GPS не гарантирует физическую точность 20 м. Принимается заявленная точность до 20 м, последняя точка должна быть не старше 15 секунд. Перерыв GPS больше 45 секунд прерывает запись. Ограничения GPS-прогулки (к покупке не относятся): максимум — 5000 точек, 2 часа, радиус 10 км от старта, площадь 25 м²–10 км². Самопересечения разрешены: замкнутые петли объединяются, внутренние границы убираются, повторный проход не удваивает площадь. Незамкнутые отростки не дают площадь; вогнутые внешние границы сохраняются. Слишком быстрые скачки GPS отклоняются. Широты за пределами ±85° и переход через линию смены дат пока не поддерживаются.

## Разбор файлов

| Файл | За что отвечает |
| --- | --- |
| `web/` | Исходники Mini App: HTML, CSS, карта, формы и GPS. |
| `web/config.mjs` | Публичный адрес вашего Supabase, без секретов. |
| `web/client.mjs` | Отправляет запросы к Edge Function; `?demo=1` выбирает отдельное локальное демо. |
| `web/numbers.mjs` | Сокращённые подписи косточек без изменения чисел в расчётах. |
| `web/fullscreen.mjs` | Полноэкранная карта, выход и перенос панели покупки. |
| `web/purchasing.mjs` | Разметка свободного участка, предварительная площадь, запрос цены и подтверждение покупки. |
| `web/demo.mjs` | Вымышленный сосед и пробный захват в браузере, без обращения к Supabase. |
| `supabase/functions/paws-api/auth.ts` | Проверка подписи Telegram и webhook-секрета. |
| `supabase/functions/paws-api/handler.ts` | API, команды бота, проверка данных, фото и вызовы RPC. |
| `supabase/migrations/202611050001_paws.sql` | PostGIS, закрытые таблицы и транзакции перезахвата. |
| `scripts/build_pages.py` | Копирует только публичные файлы `web/` в `docs/`. |
| `docs/` | Сгенерированный сайт для GitHub Pages. Руками не редактируется. |
| `scripts/configure_supabase_bot.py` | Разовое подключение webhook без сохранения токена. |
| `backend/` | Предыдущий локальный Python-сервер, оставлен для сравнения и регрессионных тестов; в Supabase не запускается. |

Edge Functions используют TypeScript (похож на JavaScript с типами), а не Python. Проверка формы маршрута перенесена в PostgreSQL/PostGIS: `старый участок − новый контур`, затем добавление участка нового владельца. Комментарии и имена функций помогают сопоставить её с прежним `backend/geometry.py`. Идентификатор профиля в этой версии совпадает с Telegram ID; имя человека, username и телефон в карточку не копируются.

После изменения `web/` выполните `python scripts/build_pages.py` и сохраните **оба** каталога в GitHub. Иначе Pages продолжит показывать старую копию. После изменения Edge Function повторите её deploy; после изменения SQL используйте новую миграцию, а не редактирование применённой истории.

- Deno: `deno task --config supabase/functions/deno.json test` — 30 тестов подписи, CORS, webhook, RPC и JPEG.
- `node tests/tracking.test.mjs`, `node tests/demo.test.mjs` и `node tests/numbers.test.mjs` — 11 тестов GPS-адаптеров, формата чисел и демо.
- `tests/postgis_checks.py` — 8 исторических проверок базовой миграции на настоящей локальной PostGIS (для v.0.7 используйте `tests/v07_checks.py`): контуры, отверстия, островки, повтор запроса, конкуренция и закрытые права. Это **не ваш Supabase**. Для теста нужен отдельный одноразовый Docker PostGIS с bootstrap из `tests/postgis_bootstrap.sql` и миграцией. Не запускайте bootstrap в облачной базе.
- `tests/v07_checks.py` — 23 проверки накопительной миграции v.0.7 в одноразовой PostGIS: пересечения, внешние границы, допуск 20 м, автозапуск трансляции, покупка и повтор оплаты, конкуренция, рейтинг площади и сохранение балансов. Нужны базовая миграция и v.0.7.
- `tests/v07_browser.py` — Chromium с подменой API/GPS: полный экран карты и поворот, сохранение GPS-прогулки/черновика, k/кк в счётчиках, рейтинги и полная цена в запросе покупки. `tests/v05_browser.py` проверяет совместимость со старым API.
- `tests/pages_smoke.py` — Chromium: сайт во вложенной папке, профиль, PNG → JPEG, демозахват, карточка и reload. Telegram SDK и тайлы подменяются, Supabase в локальном демо не вызывается.
- Прежние Python-тесты остаются доступны через `python -m unittest discover -s tests -v` после установки `requirements.txt`.

Тесты не подтверждают реальное подключение к вашему Supabase, настоящий webhook, тайлы из интернета и GPS физического телефона. Эти проверки выполняются после шагов 1–5. Никакой VPS, платный план или публичная публикация не считаются автоматически оформленными; ограничения сервисов зависят от их тарифов.

## Данные и ограничения прототипа

- Фотографии питомцев публичны по непредсказуемому адресу bucket `paws-photos`; загрузка и удаление доступны только серверной функции. JPEG повторно декодируется и кодируется без исходного EXIF.
- Обычный GPS-маршрут приходит на проверку без сохранения точек. В отдельном фоновом режиме точки временно хранятся на сервере; удаляются при завершении/отмене. Прогулки старше 2 часов завершаются и очищаются при следующем обращении к фоновому API/webhook; отдельного планировщика очистки нет. Контур территории остаётся общим. Не записывайте домашний адрес в описание питомца.
- Вход по `initData` действует до 6 часов; при истечении откройте Mini App через бота заново.
- Это базовая проверка правдоподобия GPS, не полноценная защита от подмены координат. Фоновый режим через Telegram экспериментальный; нативной фоновой записи Mini App нет. Модерация и удаление аккаунта через интерфейс ещё не реализованы.
- Общая блокировка захватов намеренно проста: для небольшой группы корректность важнее параллелизма. Для большого сервиса нужны ограничения запросов, оптимизация геометрии и нагрузки. Видно до 200 территорий текущего окна; при превышении приблизьте карту.
- Для массового использования соблюдайте [политику тайлов OSM](https://operations.osmfoundation.org/policies/tiles/) и выберите подходящий картографический сервис. Яндекс удалён; доступна подложка рельефа OpenTopoMap без ключа.
- Резервные копии PostgreSQL и Storage необходимо настроить отдельно. Секреты хранятся в Supabase Secrets, а не в репозитории.

Цвет на карте — игровая механика, он не даёт права заходить на частные или закрытые участки.
