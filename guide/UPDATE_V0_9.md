# Обновление DogWars до v.0.9

В v.0.9 изменены доход от земли, категории чата, оформление и способ записи маршрута; добавлены три камуфляжа. Существующие косточки, территории, досье, покупки Stars и репарации сохраняются.

## 1. Скачать файлы

Скачайте [ZIP v.0.9](https://github.com/igorigorigor39rus-dotcom/baza413/archive/refs/tags/v.0.9.zip) и распакуйте в новую папку. Команды ниже выполняются из папки с `README.md`, `scripts` и `supabase`.

## 2. Обновить SQL

В [Supabase SQL Editor](https://supabase.com/dashboard/project/fywsqxijebneqkxusgro/sql/new) → **New query** вставьте **весь** файл [202611060008_v09.sql](../supabase/migrations/202611060008_v09.sql) → **Run**.

Это единая накопительная миграция для v0.2–v.0.8; промежуточные SQL-файлы не нужны. Для новой установки сначала выполните базовый `202611050001_paws.sql`, затем v09. Старые миграции после v09 запускать не нужно: они возвращают прежние правила.

При первом обновлении сервер один раз фиксирует уже заработанный доход по старой ставке до момента перехода. Затем начинается новая суточная система. Повторный запуск v09 сохраняет баланс, незавершённый доход и время следующей выплаты; повторного начисления по старой ставке нет. `pg_advisory_xact_lock` в результатах — нормальная блокировка для согласованных операций.

## 3. Развернуть функцию

```powershell
npx supabase login
npx supabase functions deploy paws-api --remote=fywsqxijebneqkxusgro --no-verify-jwt
```

Подтвердите **Yes**. Затем откройте:

https://fywsqxijebneqkxusgro.supabase.co/functions/v1/paws-api/health

Ожидается `{"ok":true,"version":"0.9.0"}`. В `/api/config` должны быть `features.dailyIncome: true`, `features.geoChat: true`, `features.incomePeriodSeconds: 86400`, `features.sqmPerBone: 10`.

Секреты функции и адрес приложения остаются прежними. Если webhook и расписание были настроены для v.0.8, повторять их настройку не требуется. Для первой установки или обновления более ранней версии настройте бота и напоминания по [шагам 4–5 инструкции v.0.8](UPDATE_V0_8.md#4-обновить-webhook--обязательно-для-оплаты-stars), используя файлы из архива v.0.9. Команда для Windows, PowerShell и Git Bash:

```powershell
py -3.12 "./scripts/configure_supabase_bot.py"
```

В первом запросе вводится только токен из BotFather, во втором — `WEBHOOK_SECRET`, не `SCHEDULER_SECRET`. Символы при вводе скрыты. GitHub Pages и Supabase работают без VPS.

## 4. Проверить новые правила

Закройте Mini App и откройте его снова через бота. Интерфейс публикуется в ветке `prototype`, папке `docs`; GitHub Pages должен завершить развёртывание этой версии.

### Суточный доход

**10 м² за полные 24 часа владения дают 1 🦴.** Поэтому 100 м² дают 10 🦴 в сутки, 50 м² — 5 🦴, 5 м² — 0,5 🦴. Дробные части сохраняются.

Периоды длятся ровно 86 400 секунд с начала начислений, а не до местной полуночи. Для действующих землевладельцев первый период начинается при обновлении системы. Для нового игрока — при получении первой территории. Смена часового пояса не ускоряет выплаты. В интерфейсе показаны ставка «🦴/сутки» при текущей площади и время следующей выплаты по часам устройства.

Доход внутри периода учитывает площадь и фактическое время владения, но поступает на доступный баланс только за завершённые сутки. Неполные сутки нельзя потратить на землю. Потеря участка сохраняет накопленный за время владения доход до ближайшей выплаты.

Примеры:

- 100 м² в течение суток → 10 🦴.
- 100 м² первые 12 часов, затем земля потеряна → 5 🦴 в суточную выплату.
- 100 м² первые 8 часов, затем 50 м² оставшиеся 16 часов → 6⅔ 🦴.
- Новая земля за минуту до выплаты не даёт доход за весь прошедший день.

За несколько дней отсутствия учитываются все завершённые периоды. Баланс рассчитывается сервером при чтении и финансовых операциях; для получения дохода не нужно держать приложение открытым. Планировщик напоминаний не требуется для самого расчёта дохода. В таблице кошельков хранятся последняя зафиксированная сумма и время расчёта; API и рейтинг показывают актуальную сумму с завершёнными выплатами.

Купленные через Stars косточки и репарации поступают сразу. Для них ожидания суток нет. Остаток по возвратам погашается доступными начислениями по прежним правилам, а незавершённый суточный доход не становится доступным досрочно. Цена земли остаётся **10 🦴/м²**. При физическом GPS-захвате репараций нет.

### Категории чата

| Категория | Кто видит | Кто пишет |
| --- | --- | --- |
| Район | Игроки, чьи ориентиры крупнейших участков находятся не дальше 2 км друг от друга | Эти же игроки со своим досье и территорией |
| Город | То же правило с радиусом 20 км | Эти же игроки со своим досье и территорией |
| Мир | Все вошедшие через Telegram, включая игроков без земли | Игроки с суммарной площадью своих участков **от 1 000 000 м² включительно** |

Ориентир — вычисленная сервером точка внутри самого большого участка, соответствующая его геометрии. Это не текущее GPS-положение телефона: разрешение геолокации для выбора чата не требуется. Расстояние считается по поверхности Земли в метрах. Учитываются все принадлежащие игроку участки, включая купленные. Для порога «Мира» площадь нескольких участков складывается.

Категории хранят сообщения раздельно. Прежние сообщения общего чата остаются в «Мире». При изменении крупнейшей территории игрока или собеседников состав видимых локальных сообщений пересчитывается; сообщение не переносится между категориями. Без своей земли доступны чтение «Мира» и пояснение в локальных вкладках. В мировом чате поле ввода заблокировано до достижения порога; после потери нужной площади сервер снова запрещает отправку.

Проверка действует в базе и API, поэтому старый клиент или ручной запрос не обходят ограничения. Ограничение частоты — одно сообщение за 3 секунды на игрока суммарно по категориям. Чат остаётся на весь экран, фото и тексты не вставляются как HTML.

### Комиксное оформление

Сохранена графитовая палитра. Заголовки и интерфейс используют локальный Balsamiq Sans с кириллицей, а кнопки и панели — выраженные контуры и плотные тени. Добавлены рисованные иконки и облачка сообщений; вкладки и досье оформлены в одном стиле. Шрифты находятся в `web/assets/fonts`, лицензия SIL OFL приложена. Приложение не загружает шрифты с внешних сервисов.

В «Мире» есть компактная плашка с порогом **1 000 000 м² (100 га)** и пояснением «Масштаб лая подтверждается гектарами 🐾». Она видна всем читателям мирового чата.

### Один способ записи: трансляция Telegram

Кнопки «Начать захват» и «Гулять с выключенным экраном» удалены из Mini App. Вместо них показана инструкция и кнопка **«Открыть чат бота»**. Она отправляет инструкцию в чат и возвращает пользователя в Telegram, не включая GPS в Mini App.

1. Откройте личный чат бота.
2. Нажмите 📎 → **Геопозиция → Транслировать геопозицию**. Обычная отправка разовой точки не подходит.
3. Запись начнётся с первой точки с погрешностью не больше 20 м.
4. Пройдите замкнутый маршрут, вернитесь в пределах 20 м от старта и дождитесь свежей точки GPS.
5. Нажмите **«Захватить»** в сообщении бота или отправьте `/capture`.
6. После успешного захвата остановите трансляцию в Telegram и откройте карту.

Если трансляция ещё не включена, остановлена или истёк её срок, бот отвечает:

> Включите трансляцию: 📎 → Геопозиция → Транслировать геопозицию. Затем пройдите маршрут и нажмите «Захватить».

Остановка трансляции сама по себе не отдаёт землю и не удаляет незавершённые точки. Новая трансляция после остановленной/истёкшей начинает новый маршрут, без склейки точек разных прогулок. Старое повторное обновление Telegram не включает остановленную запись. Повтор уже завершённого захвата возвращает прежний результат.

Старые API браузерного старта и отправки GPS-маршрута отклоняются с понятной инструкцией. Старые незавершённые браузерные сессии заменяются новой трансляцией. Проверки замыкания, точности, средней скорости 20 км/ч, временных пропусков и отсутствия репараций при GPS остаются прежними. Кнопка «Найти меня» только центрирует карту и не записывает маршрут. Локальный демо-маршрут остаётся учебным примером без реального GPS и общей карты.

### Три новых камуфляжа

В досье → «Узор» добавлены:

- **Цифровой:** группы квадратных пикселей разных размеров и тонов.
- **Тигровый:** длинные прерывистые полосы, похожие на мазки кистью.
- **Flecktarn:** группы мелких пятен, образующих неоднородную поверхность.

Рисунки различаются геометрией и одинаково отображаются в предпросмотре и на карте. Новые варианты используют выбранные Hue и насыщенность, а плотность заливки регулирует общую прозрачность. Прежний классический камуфляж, полоски, сетка и сплошная заливка сохраняются.

Основа выбора: [пиксельный/многоуровневый камуфляж](https://en.wikipedia.org/wiki/Multi-scale_camouflage), [Tigerstripe](https://en.wikipedia.org/wiki/Tigerstripe), [Flecktarn](https://en.wikipedia.org/wiki/Flecktarn). Для карты созданы собственные векторные рисунки с настраиваемым цветом.

## Проверки перед использованием

1. Откройте правила и убедитесь, что видите `10 м² × 24 часа = 1 🦴`, а счётчик показывает доход за сутки.
2. Проверьте «Район» и «Город» с двумя аккаунтами в соответствующем радиусе крупнейших участков.
3. Аккаунтом без земли откройте «Мир»: чтение доступно, отправка заблокирована.
4. При общей площади ровно 1 млн м² отправка в «Мир» становится доступной; после потери площади — блокируется.
5. Покупка косточек Stars и выкуп земли работают по прежним ценам и с прежними репарациями.

Пройдено 55 проверок PostGIS, 46 проверок Edge Function/API, Node-проверки, мобильные браузерные сценарии и установка с нуля со схемой PostGIS `extensions`. Проверки разработки используют одноразовую PostGIS, локальный браузер и подменённые Telegram/API/GPS. Публикация GitHub сама не применяет SQL или Edge Function в рабочем Supabase: шаги 2–3 выполняет владелец проекта.
