# Единая инструкция обновления до v.0.5

Для работающего приложения v0.2, v0.3 или v.0.4. Профили, территории, фотографии и начисленные 🦴 сохраняются. Устанавливать промежуточные версии не нужно.

## 1. Скачать релиз в новую папку

Скачайте [ZIP v.0.5](https://github.com/igorigorigor39rus-dotcom/baza413/archive/refs/tags/v.0.5.zip), распакуйте. Откройте папку, внутри которой находятся README.md, supabase и scripts. Старые локальные файлы не подмешивайте к новому архиву.

## 2. Выполнить один SQL-файл

Откройте [проект Supabase](https://supabase.com/dashboard/project/fywsqxijebneqkxusgro) → **SQL Editor → New query**.

1. В новом архиве откройте `supabase/migrations/202611060003_v05.sql` любым текстовым редактором.
2. Скопируйте **всё содержимое**, вставьте в SQL Editor.
3. Нажмите **Run** и дождитесь успешного выполнения.

Это накопительная миграция. Базовую миграцию и файлы v0.3/v.0.4 повторно запускать не нужно. Пустая ячейка результата `pg_advisory_xact_lock` нормальна: это блокировка на время согласованного обновления, она освобождается автоматически при завершении транзакции. Если видите ошибку, не запускайте отдельные куски SQL — пришлите текст ошибки без секретов.

Для совершенно нового проекта сначала нужна базовая миграция `202611050001_paws.sql`, затем этот файл; см. README. Повторное выполнение v.0.5 не сбрасывает баланс.

## 3. Обновить Edge Function

В Проводнике откройте новую папку проекта, нажмите адресную строку, введите `cmd`, нажмите Enter. Выполните:

```sh
npx supabase functions deploy paws-api --remote=fywsqxijebneqkxusgro --no-verify-jwt
```

Если CLI просит войти: `npx supabase login`, затем повторите команду. На вопрос о загрузке **paws-api** в ваш проект отвечайте **Yes**. Старый CLI использует `--project-ref` вместо `--remote`.

Существующие `TELEGRAM_BOT_TOKEN`, `APP_URL` и `WEBHOOK_SECRET` в Supabase Secrets сохраняются. Создавать нового бота или новый секрет для обновления не требуется.

## 4. Проверить сервер

Откройте [проверку готовности](https://fywsqxijebneqkxusgro.supabase.co/functions/v1/paws-api/health). Ожидается:

```json
{"ok":true,"version":"0.5.0"}
```

Затем откройте [конфигурацию API](https://fywsqxijebneqkxusgro.supabase.co/functions/v1/paws-api/api/config). Проверьте `version: "0.5.0"`, `closureMeters: 15`, в `features` — `liveTracking` и `leaderboard`: true. Если версия старая, не обновилась функция. Если флаги false или health сообщает об ошибке — проверьте выполнение SQL и Secrets.

## 5. Обновить webhook для трансляции геопозиции

**Этот шаг нужен и при обновлении уже работающего бота.** Telegram передаёт перемещение через `edited_message`; прежний webhook принимал только новые сообщения.

В том же окне cmd, из корня новой папки, выполните:

```bat
py -3.12 scripts\configure_supabase_bot.py
```

Для macOS/Linux: `python3.12 scripts/configure_supabase_bot.py`.

Введите действующий токен бота, затем **тот же WEBHOOK_SECRET**, который хранится в Supabase Secrets. При вводе символы не показываются — это нормально. Не отправляйте токен или секрет в чат. Скрипт проверит Pages, API и совпадение настроек, включит `message` + `edited_message`, обновит меню и команды `/status`, `/capture`, `/cancel`. Накопленные сообщения Telegram не удаляются.

Если пишет, что файл не найден, убедитесь, что текущая папка содержит `scripts`; не добавляйте второй префикс `scripts`. Python нужен только для разовой настройки, держать компьютер включённым не нужно.

## 6. Прогулка с выключенным экраном

Это **отдельный экспериментальный режим Telegram**. Обычная кнопка «Начать захват» по-прежнему требует открытого Mini App. Telegram и ОС определяют, как часто приходят координаты в фоне: обещать непрерывную запись на каждом телефоне нельзя.

1. Полностью закройте Mini App и снова откройте через бота. Создайте досье питомца, если его ещё нет.
2. Выйдите на открытое место. Нажмите **«С выключенным экраном · Telegram»**, разрешите точную геолокацию. Старт разрешён при заявленной погрешности GPS **не больше 15 м**.
3. Нажмите **«Перейти в чат бота»**. В личном чате бота нажмите **скрепку → Геопозиция → Транслировать геопозицию**. Выберите, например, 1 час. Обычная разовая отправка местоположения не подходит.
4. Разрешите Telegram точную геопозицию и доступ к ней в фоне в настройках iOS/Android. При необходимости снимите ограничение энергосбережения для Telegram. Названия пунктов зависят от телефона.
5. Дождитесь сообщения **«Фоновая запись началась»**. Команда `/status` покажет число принятых точек, точность и возраст последней. Если точность не передаётся или хуже 15 м, точка пропускается; сервер не считает её точной автоматически.
6. Теперь можно выключить экран и обойти участок. Telegram должен иметь интернет и продолжать трансляцию. Максимальная прогулка — 2 часа.
7. Вернитесь **в пределах 15 м от первой принятой точки**, включите экран, дождитесь свежего обновления геопозиции. Выполните `/capture` либо откройте карту и нажмите **«Захватить фоновый маршрут»**. Последняя точка должна быть не старше 15 секунд и с погрешностью не больше 15 м.
8. После успеха **остановите трансляцию геопозиции в Telegram**. `/cancel` отменяет незавершённую прогулку и удаляет её временные точки; после него также остановите трансляцию самостоятельно.

Нужно минимум 4 принятые точки и замкнутый контур без самопересечений. Пропуск между принятыми точками больше 45 секунд, скачки GPS, слишком большой/маленький участок отклоняются. После ошибки с пропусками отмените прогулку и начните новую. Если ваш телефон редко обновляет координаты в фоне, используйте обычную запись с открытой картой. Допуск замыкания 15 м относится к измеренным координатам, а не к гарантированной физической точности GPS.

Фоновый маршрут восстанавливается при повторном открытии карты, поскольку точки принимает сервер через webhook. Они хранятся в закрытой таблице и удаляются при успешном захвате/отмене. Прогулки старше 2 часов завершаются и очищаются при следующем обращении к фоновому API/webhook. Отдельного расписания очистки нет: без обращений срок удаления может быть больше 2 часов. Контур захваченной территории остаётся общим.

## 7. Проверить остальные изменения

- Приблизьте/отдалите карту: фото питомцев увеличиваются/уменьшаются вместе с масштабом.
- В досье выберите «Камуфляж»: военная woodland-текстура должна появиться в предпросмотре и на территории после сохранения. Hue слегка тонирует её, плотность регулирует прозрачность.
- Откройте «Оперативную связь»: чат занимает весь экран, список прокручивается, кнопка закрытия доступна.
- Откройте **«ТОП-10 Агентов»**: до 10 профилей по убыванию актуального баланса 🦴, включая ещё не зафиксированный доход. При равенстве балансов порядок определяется ID. Нажатие имени открывает досье.
- В «Правила 🦴» сохранена формула **1 м² × 1 час = 1 🦴**; строка о старых участках удалена.
- Обычный GPS-захват тоже использует допуск замыкания **15 м**, при заявленной точности точек ≤15 м. Подсказка на карте показывает текущий порог сервера.

Карты остаются OpenStreetMap и OpenTopoMap без платного ключа. Демо: https://igorigorigor39rus-dotcom.github.io/baza413/?demo=1 — локальные территории, чат и рейтинг. Фоновый режим в демо отключён: он требует настоящего Telegram webhook.

## Публикация и проверка

GitHub Release содержит файлы, GitHub Pages публикует интерфейс из `prototype /docs`. Они не устанавливают SQL, Edge Function или webhook. Доступа к вашим Supabase Access Token/паролю базы в среде разработки нет, поэтому шаги 2–5 выполняет владелец. Секреты в переписку присылать не нужно.

Проверено: 23 теста Edge Function, 23 Python-теста, 7 Node-тестов; 13 проверок схемы в одноразовой PostGIS; браузерные сценарии камуфляжа, зума, полного экрана чата, рейтинга, GPS-порога и восстановления фоновой прогулки. Браузерные сценарии используют подменённые Telegram SDK/API/GPS. Фоновую работу настоящего телефона нужно проверить короткой прогулкой после установки.
