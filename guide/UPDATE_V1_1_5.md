# Обновление DogWars до v.1.1.5

Исправлена ошибка **21000 / UPDATE requires a WHERE clause** при захвате территории. Причина подтверждена журналом Supabase: триггер `bump_sync_revision()` обновлял служебный счётчик без `WHERE`, а защитный модуль `safeupdate` запрещает такие запросы. Теперь обновляется строка с ключом `id=true`. Защита остаётся включённой, игровые правила не меняются.

## Для ручной установки с v.1.1.4

1. [Скачайте архив v.1.1.5](https://github.com/igorigorigor39rus-dotcom/baza413/releases/download/v.1.1.5/baza413-v.1.1.5.zip) и распакуйте в новую папку.
2. Supabase → проект **fywsqxijebneqkxusgro** → **SQL Editor → New query**.
3. Скопируйте весь файл `supabase/migrations/202611160001_sync_revision_where.sql`, вставьте и нажмите **Run**.
4. Из папки нового архива загрузите функцию:

```powershell
npx supabase functions deploy paws-api --remote=fywsqxijebneqkxusgro --no-verify-jwt
```

Если нужна авторизация, сначала выполните `npx supabase login`. На вопрос о загрузке ответьте **Yes**. Старые миграции повторять не нужно.

## Проверка

Откройте https://fywsqxijebneqkxusgro.supabase.co/functions/v1/paws-api/health — ожидается:

```json
{"ok":true,"version":"1.1.5"}
```

В `/api/config` должен быть `features.safeSyncRevision: true`. Если `/health` просит новый SQL, выполните шаг 3; если версия осталась `1.1.4`, повторите загрузку функции из новой папки.

После обновления нажмите **«Захватить»** в боте для сохранённого активного маршрута. Сама установка его не завершает и не захватывает территорию. Анкеты, точки маршрута, участки, балансы и текущее значение счётчика при установке SQL сохраняются. Токен бота и `WEBHOOK_SECRET` не меняются; `configure_supabase_bot.py` запускать повторно не нужно.

## Почему пробный SQL-захват мог проходить

У роли API `authenticator` модуль `safeupdate` загружается при подключении. Смена роли через `SET ROLE service_role` внутри административной сессии этот модуль не загружает. Поэтому проба из SQL Editor могла пройти, а запрос через бота — получить 21000. Для воспроизведения в локальной PostGIS использован настоящий модуль [pg-safeupdate](https://github.com/eradman/pg-safeupdate) и тест `tests/safeupdate_checks.py`.

Проверены исходный отказ 21000, завершение того же тестового маршрута после исправления, повтор захвата без второй территории, изменение существующей территории, сохранение анкеты, сохранность данных при повторной миграции и сохранение запрета неограниченных UPDATE. Проверка рабочего маршрута выполнялась с откатом; реальное завершение остаётся действием игрока.
