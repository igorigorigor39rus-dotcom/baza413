DogWars v.1.1.5: исправление ошибки 21000 при захвате территории.

В Supabase подтверждён сбой `UPDATE requires a WHERE clause`: триггер служебного счётчика обновлений карты/чата выполнял UPDATE без WHERE, который блокировался модулем `safeupdate` в запросах API. Добавлено условие `WHERE id=true`; защитный режим остаётся включённым.

- Сохранённый маршрут можно завершить после установки исправления; сама миграция территорию не захватывает.
- Маршруты, участки, анкеты, балансы и значение счётчика при миграции сохраняются. Игровые правила и отсутствие лимита времени не меняются.
- `/health` проверяет флаг исправления `safeSyncRevision` и сообщает версию 1.1.5.

**Для ручного обновления с v.1.1.4:** сначала выполните `supabase/migrations/202611160001_sync_revision_where.sql`, затем загрузите `paws-api`. [Пошаговая инструкция](https://github.com/igorigorigor39rus-dotcom/baza413/blob/v.1.1.5/guide/UPDATE_V1_1_5.md). Новые токены и повторная настройка webhook не нужны.

Проверены 74 API-теста и 4 сценария в настоящей PostGIS с загруженным pg-safeupdate: старый код воспроизводит 21000, исправленный завершает тот же маршрут и корректно обрабатывает повтор. Проверены изменение существующей земли, сохранение профиля, права, данные и работа защитного запрета после исправления. Административный SQL без загруженного safeupdate не считается воспроизведением контекста API.
